Lição 0001 · Active Record na Margem

Valores sem o model

Quando a API precisa de um ISBN, um id ou uma lista de títulos, peça a coluna. Não carregue um Book para jogar o resto fora.

Book e User herdam a interface de consulta porque são subclasses de ApplicationRecord. Essa classe chama primary_abstract_class: vira a classe abstrata da aplicação, liga o banco primário e não tem tabela própria. Quem consulta é Book, não ApplicationRecord. A definição está na API de primary_abstract_class.

class ApplicationRecord < ActiveRecord::Base
  primary_abstract_class
end

Três retornos

O guia, na seção Finding Records and Values, separa métodos que devolvem valores crus. Três bastam para a Margem. Os três disparam a SQL na hora.

ChamadaDevolveUse quando
pluck Array de valores várias linhas, uma ou mais colunas
pick o valor da primeira linha, ou nil você já sabe que quer uma linha
ids Array da chave primária só os id da relação

pluck aceita colunas e devolve os valores no tipo da coluna, sem construir objetos Book. Por isso um método redefinido no model não roda: o guia mostra um first_name sobrescrito que aparece em select + map e some no pluck.

Book.where(category: "Poesia").pluck(:isbn)
# => ["9788500000001", "9788500000002"]

Book.where(category: "Poesia").pluck(:id, :title)
# => [[3, "O guardador de rebanhos"], [4, "Alguma poesia"]]

pick é o atalho de limit(1).pluck(...).first. Uma coluna devolve o valor; várias colunas devolvem um array dessa única linha.

User.where(email: email).pick(:id)
# => 12   ou nil

User.find_by(email: email)
# => #<User id: 12, ...>   ou nil

O login da Margem usa find_by porque precisa do User inteiro para a senha. pick(:id) serviria se a próxima linha só usasse o número.

ids é pluck da chave primária. Em Book e User essa chave é id. Se a chave tivesse outro nome, ids acompanharia esse nome.

Book.where(category: "Tecnologia").ids
# => [8, 9, 14]

A cadeia acaba

Book.alphabetical.search(params[:q]) no index ainda é uma relação: dá para continuar com page. pluck, pick e ids executam e devolvem Array ou um valor. O que vier depois não é consulta.

Book.limit(1).pluck(:isbn)          # funciona
Book.pluck(:isbn).limit(1)          # NoMethodError: limit em Array

select continua sendo relação e ainda instancia models com as colunas pedidas. pluck não. O guia também avisa: pluck numa relação que já tem includes dispara o eager load mesmo sem precisar das associações. unscope(:includes) tira isso antes do pluck.

Recupere sem olhar acima

Responda uma vez. As quatro opções de cada pergunta têm o mesmo número de palavras.

Confira no console

Com a API no ar, a partir da raiz do repositório:

docker compose exec api bundle exec rails console
  1. Book.limit(1).class deve imprimir uma relação, não um Book.
  2. Book.limit(1).pluck(:isbn).class deve ser Array.
  3. Book.pick(:isbn).class deve ser String ou NilClass.
  4. Book.limit(1).ids deve ser um array com um inteiro, ou vazio se não houver livro.

Se o segundo item não for Array, a consulta não disparou do jeito que o guia descreve. Manda o que apareceu.
