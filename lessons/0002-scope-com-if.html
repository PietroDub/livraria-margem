Lição 0002 · Active Record na Margem

Scope com if

Book.search pode continuar scope. O if não é o critério. O critério é cada ramo devolver uma relação, para alphabetical e page continuarem na mesma consulta.

No guia, scope com argumento é a mesma coisa que um class method. A API chama isso de açúcar sintático: scope :nome, -> { ... } define def self.nome. A seção Using Conditionals mostra um if dentro do scope.

O que o if não pode devolver

Um scope cujo corpo devolve nil ou false vira a relação corrente. O Rails faz isso em _exec_scope: instance_exec(...) || self, e esse self é a relação. Um class method que cai no mesmo if devolve nil. Aí .page chama método em nil e estoura NoMethodError. O guia escreve esse aviso na seção 17.2.

scope :created_before, ->(time) { where(created_at: ...time) if time.present? }
# tempo ausente: ainda é relação

def self.created_before(time)
  where(created_at: ...time) if time.present?
end
# tempo ausente: nil

O search da Margem

Os dois ramos já devolvem relação: all sem termo, where com termo. Por isso o index pode escrever isto com o termo vazio:

Book.alphabetical.search(params[:q]).page(params[:page])

all, chamado com uma relação já em curso, clona essa relação. A ordem de alphabetical permanece e o page entra nela. Está em Scoping::Named::ClassMethods#all no Rails 8.1: se existe current_scope do mesmo model, o retorno é scope.clone.

Um def self.search com os mesmos all e where se comporta igual. A relação, ao receber search, executa scoping { model.search(...) }. Durante esse bloco, all e where enxergam a cadeia anterior.

O exemplo do guia que devolve self no class method devolve a classe Book, porque dentro de def self.search o self é a classe. Nessa cadeia do index, a ordem de alphabetical ficaria de fora. O ramo vazio deste model é all.
